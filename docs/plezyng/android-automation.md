# Android automation links

Pleazyng registers Android `ACTION_VIEW` handlers for `pleazyng://` links. They can launch media, switch to an existing profile, or control an active video session.

## Link forms

| Link | Action |
| --- | --- |
| `pleazyng://watch?...` | Resolve and play a movie or a show's next/shuffled episode from connected Plex, Jellyfin, or Emby servers. Copy a generated link from a movie or show detail page. |
| `pleazyng://profile?id=<profile-id>` | Switch to a local or Plex Home profile. Copy this from that profile's detail page. Normal local PIN and Plex Home PIN checks still apply. |
| `pleazyng://control?command=play` | Resume the active video session. |
| `pleazyng://control?command=pause` | Pause the active video session. |
| `pleazyng://control?command=toggle` | Toggle play/pause on the active video session. |
| `pleazyng://control?command=stop` | Stop the active video session and leave the player. |

`control` links only address the active video player; they cannot start arbitrary content. A `watch` link can be generated from the media detail page and is resolved against the connected servers. The profile detail screen provides a copy action for the profile URI.

## Launch from Android Debug Bridge

The Android shell can open any registered link directly:

```sh
adb shell am start -a android.intent.action.VIEW -d 'pleazyng://control?command=pause'
```

Replace the URI with a generated watch or profile link. Query values must be URL-encoded when constructing links manually.

## Home Assistant

Home Assistant's [Android Debug Bridge integration](https://www.home-assistant.io/integrations/androidtv/) can send ADB shell commands to Android TV and Fire TV devices. Enable ADB debugging on the device and authorize Home Assistant's connection first. The integration's [`androidtv.adb_command` action](https://www.home-assistant.io/actions/androidtv.adb_command/) accepts an ADB shell command.

For example, this script pauses the current Pleazyng video on an Android TV device:

```yaml
script:
  pause_pleazyng:
    alias: Pause Pleazyng
    sequence:
      - action: androidtv.adb_command
        target:
          entity_id: media_player.living_room_tv
        data:
          command: am start -a android.intent.action.VIEW -d 'pleazyng://control?command=pause'
```

To play media, pass a `pleazyng://watch` URI generated by Pleazyng in the same command. To change profiles, use the profile URI copied from its detail page; if that profile is protected, complete the PIN prompt on the device before sending a separate watch link.

This is an Android intent bridge. It does not register Pleazyng as a native Plex Companion client in Home Assistant's Plex integration, whose media-player support targets connected Plex clients. The bridge also does not create a native Plex/Jellyfin/Emby media-player entity in Home Assistant.

## Upstream sources

These authors made the linked contributions or suggestions to upstream Plezy.
Pleazyng independently adapted or reviewed the relevant behavior; the feature
status and limits above remain authoritative.

- Media watch-link foundation: [PR #2681](https://github.com/edde746/plezy/pull/2681) by [@razzamatazm](https://github.com/razzamatazm).
- External/Home Assistant control request: [issue #823](https://github.com/edde746/plezy/issues/823) by [@Deathbot64](https://github.com/Deathbot64).
- Android intent automation request: [issue #1996](https://github.com/edde746/plezy/issues/1996) by [@npike](https://github.com/npike).

The current generated scheme is `pleazyng://`. Profile selection and active-video
commands are downstream extensions; the Android intent bridge does not provide
the native Plex Companion integration requested by some upstream users.
