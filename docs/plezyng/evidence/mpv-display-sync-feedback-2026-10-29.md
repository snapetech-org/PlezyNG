# MPV display-sync feedback source change

Patch 0161 adds matched display-sync feedback to desktop PME. MPV publishes a per-source-frame record containing the source PTS, final vsync count after A/V correction, vsync interval, effective video speed, and display-sync error before and after scheduling. PME consumes a record only when the PTS, interval, and speed match the source pair being processed.

For a matched record, PME converts selected display-slot edges back to media PTS using the scheduler's pre-frame error and playback speed, then omits any phase outside the source interval. It converts post-frame timing error into slot units for the next pair. Startup, reset, and mismatched feedback use the deterministic nominal-grid fallback. Filter metadata and the PlezyNG overlay identify MPV display-sync feedback versus the nominal grid.

Patch 0161 is now compiled into local package candidates for Linux x86_64/aarch64 and Windows x86_64/aarch64. The Linux aarch64 package passed `zstd -t`; its symbols ZIP passed `unzip -t`; its shared library identifies as ELF64 AArch64 and includes the display-sync, timing-source, and configured-phase-budget identifiers. See the [artifact gate evidence](mpv-motion-artifact-gate-2026-10-29.md) for hashes and retained paths.

Android uses a separate MPV patch series and does not consume desktop-only patch 0161. The Android live preset-switch implementation was compiled and packaged together with the full default LiteRT model set in the [combined 12-model APK](android-12-model-apk-build-2026-10-30.md). An in-session Performance/Balanced/Quality switch serializes filter/provider replacement and prepares the requested model/runtime before swapping. It attempts to restore the previous preset if setup fails, and Android can fall back to MPV smoothing if restoration fails. First-time Neural activation and unsupported decoder/renderer transitions remain staged for the next media open. A short frame gap may occur during replacement.

These artifacts establish source compilation and packaging only. No Android, Linux, or Windows device/display playback was performed. Provider placement, visible interpolation quality, cadence, A/V sync, and sustained playback remain unqualified. PlezyNG remains pinned to the published MPV package group; no candidate package was uploaded and no CI workflow was run.
