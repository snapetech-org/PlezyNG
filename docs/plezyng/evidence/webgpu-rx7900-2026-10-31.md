# Linux WebGPU runtime bundle on the dual-GPU desktop

**Date:** 2026-10-31

**Host:** `kspld0`

**Compute GPU:** AMD Radeon RX 7900 XT (`vendor=0x1002`, `device=0x744c`)

**Desktop/output GPU:** AMD Radeon RX 9070 XT (`vendor=0x1002`, `device=0x7550`)

The local Linux CMake variant packages ONNX Runtime 1.27.1 with the pinned
ONNX Runtime WebGPU Plugin EP 0.5.0. The WebGPU plugin, manifest, PME library,
ORT runtime chain, and notices are installed into the Flutter app bundle's
`lib/` directory. The app's existing motion service discovers this directory
next to the bundled executable. The WebGPU provider uses the system Vulkan
loader and driver; it does not require the ROCm userspace runtime.

## Local app build

Flutter 3.47.1 generated the Linux configuration, then CMake built and installed
the app in an isolated build directory with `PLEZY_ORT_LINUX_VARIANT=webgpu`:

```sh
flutter build linux --debug --config-only
cmake -S linux -B build/pme-webgpu-app -G Ninja \
  -DCMAKE_BUILD_TYPE=Debug \
  -DFLUTTER_TARGET_PLATFORM=linux-x64 \
  -DPLEZY_ORT_LINUX_VARIANT=webgpu
cmake --build build/pme-webgpu-app --target install --parallel 8
```

The installed bundle contains `lib/libplezy_motion_engine.so`,
`lib/libonnxruntime.so.1.27.1` and its symlinks,
`lib/libonnxruntime_providers_shared.so`,
`lib/libonnxruntime_providers_webgpu.so`, `lib/providers.linux.tsv`, and the
WebGPU license and third-party notices. The provider manifest points to the
provider library beside itself. The bundle occupies about 708 MB, including
the other Linux app dependencies.

## RX 7900 XT selection and runtime smoke

`scripts/motion/with_rx7900_motion_gpu.sh` resolved the RX 7900 XT by ROCm name
and UUID, mapped it to Vulkan IDs `0x1002:0x744c`, and set those IDs for PME's
WebGPU selector. It verified that the ROCm-visible device set contained only
the RX 7900 XT. The RX 9070 XT remains selected independently by the desktop
and MPV output path.

The PME runtime probe used the just-built app bundle's ONNX Runtime and provider
manifest, with CPU fallback disabled:

```sh
PLEZY_PME_RUNTIME_DIR="$PWD/build/pme-webgpu-app/bundle/lib" \
  scripts/motion/with_rx7900_motion_gpu.sh \
  "$PWD/build/pme-webgpu-app/runner/plezy_motion_engine/plezy_motion_runtime_probe" \
  "$PWD/build/pme-webgpu-app/bundle/lib/libonnxruntime.so" \
  "$PWD/build/pme-webgpu-app/bundle/lib/providers.linux.tsv" \
  "$PWD/assets/motion_models/anvil-s-540p.onnx" \
  WebGpuExecutionProvider 0 3
```

The probe opened `WebGpuExecutionProvider` on an AMD GPU in 324.208 ms. With
zero warmups and three timed calls, it reported 24.264 ms median, 33.261 ms p95,
and 26.719 ms mean. It reported `cpu_execution=false` and
`cpu_fallback=false`. The PME shared library also resolved from the app bundle's
`lib/` directory when the probe ran.

An earlier three-call WebGPU probe was measured while an unrelated existing
`llama-server` workload used about 94% of the RX 7900 XT and 20.47 of 21.46 GB
of its VRAM. That process was left running. These short probes establish that
the selected provider, device pin, model, and bundled runtime execute without
CPU fallback. They are not frame-budget qualification and do not establish
visible playback, display pacing, A/V sync, image quality, sustained thermal
behavior, or performance under an otherwise idle GPU.

The retained local bundle is at
`build/pme-webgpu-app/bundle/plezy`; the CMake build tree is
`build/pme-webgpu-app`. No CI build or workflow dispatch was used.
